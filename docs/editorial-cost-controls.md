# 早报生成的成本控制

游戏雷达启用时，独立分配总工具预算的一半（向上取整）。默认正式6次拆为普通新闻3次、游戏3次；预览默认2次拆为1+1，核验能力有限时显示检索不足。只启用游戏时全部用于游戏；关闭游戏或推荐数量为0时全部用于普通新闻。每个通道独立缓存、记录用量，预算不叠加。游戏通道要求专项发现候选并预留打开原文的机会；未完成核验、超时或检索不足时如实标记，不解释为没有值得推荐的游戏。只有核验并通过来源、偏好和历史去重检查的候选才能入选。

正式流程：轻量模型检索 → 轻量模型整理候选 → 本地去重、来源与偏好检查 → 强模型编稿一次 → 按日期存档。

## 配置

在服务器 `.env.local` 配置，修改后重启服务。不要把密钥放进网页。

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| EDITORIAL_MODE | production | production / preview / mock / voice-test |
| EDITORIAL_DISCOVERY_MODEL | gpt-5.4-mini | 检索 |
| EDITORIAL_SHORTLIST_MODEL | 同检索模型 | 候选整理 |
| EDITORIAL_FINAL_MODEL | EDITORIAL_MODEL 或 gpt-6-astra | 正式编稿 |
| EDITORIAL_MAX_TOOL_CALLS | 正式6，预览2 | 正式最多8，预览最多3 |
| REALTIME_MODEL | 保留现有配置 | 用户点击播报后才连接 |

预览的最终编稿使用检索模型，数据存在 `data/preview/`，不替换正式早报。正式输出上限依次为6000、7000、16000 tokens；预览为3500、4500、8000。

Mock 和 Voice Test 复用已有正式存档，不生成、不搜索。没有今天的存档时页面可以展示以前的存档；没有任何存档时需要先提供经过验证的测试早报。Voice Test 的语音连接仍会产生语音服务费用。Mock 的模型生成入口被禁止；本地自动测试模拟语音连接。

打开页面时，由服务器仅为缺失的当天早报安排生成；文件锁防并发，已有有效早报直接复用。失败后不会自动重试，每日最多三次尝试。检索结果缓存24小时。维护脚本必须显式携带 `--regenerate` 才能进行付费生成，输出仍供审核。

最终编稿只收到入选候选的压缩证据和已核对的来源，不能收到完整检索文本。分类偏好和游戏雷达资格检查继续生效。暂停播报两分钟后关闭连接，继续时重新连接并恢复位置。

## 用量检查

`data/telemetry/editorial.jsonl` 记录日期、模式、阶段、模型、响应ID、输入/输出tokens、web_search调用次数和缓存命中。失败且服务端未返回用量时记为未知，不当作零费用。此文件仅供维护，不显示在主界面。

不预设费用金额，也不把 token 上限当作金额上限。实际节省比例需用后续真实生成记录和账户账单比较；新轻量模型的账户可用性和实际内容质量还需要真实生成验收。
