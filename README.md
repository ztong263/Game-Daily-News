# Game Daily

面向独立开发者的中文每日早报。打开页面自动准备当天内容，已有内容直接复用；播报中点击麦克风开始提问，再次点击结束录音并发送。默认不收录环境声音。

选题覆盖工具与工作流、行业与平台、设计思考、独立开发案例、游戏雷达。游戏雷达每期0–2款，计入总计最多7条，依据可核实的官方页面与设计学习价值筛选，不强制每日推荐。左下角设置可保存内容分类、游戏推荐数量及关注主题；偏好保存在 DATA_DIR 下的 preferences.json。质量门槛和排序权重仍集中在 `lib/editorial/radar-config.ts`。生成开始时读取一次偏好，贯穿检索、筛选、编写和发布校验；偏好参与研究缓存标识，不会重写已经准备好的当天早报。页面根据返回的数据展示作品状态、推荐理由及游玩观察问题。

## 本机运行

需要 Node.js 24、OpenAI API 项目权限及可用额度。

1. npm install
2. 在未跟踪的 .env.local 配置 OPENAI_API_KEY；已有安全配置的文件不要覆盖。
3. npm run dev
4. 打开 http://127.0.0.1:3000 。首次早报生成可能需要几分钟。

生产模式：npm run build，然后 npm start。两种启动默认只监听本机。不要直接暴露到公网。

## 六个模块

- lib/brief/schema.ts：数据契约和时区日期。
- lib/editorial/research.ts：独立新闻检索；selection.ts：选题评分与去重；generate.ts：编辑与结构化输出；rules.ts：独立编辑规则。
- lib/server/store.ts：按天保存任务、早报和审计记录；文件锁防止重复生成。
- lib/broadcast/controller.ts：不依赖 API 的段落进度状态机。
- lib/realtime/client.ts：浏览器语音、文本事件和控制器连接。
- app/page.tsx：目录、内容卡片、文字对话、状态和输入栏。

服务端接口：GET /api/brief/today 查询；POST /api/brief/today 请求准备；POST /api/realtime/session 创建 WebRTC 会话。浏览器不会收到长期密钥。

## 配置

.env.example 只包含变量名和公开默认值。
EDITORIAL_MODEL 和 REALTIME_MODEL 可替换账户支持的模型；REALTIME_VOICE 控制声音；BRIEF_TIMEZONE 默认 Australia/Sydney；DATA_DIR 默认 ./data。

当前默认模型已通过账户模型列表检查；实际生成是否成功仍受账户余额、速率与服务状态影响。

## 存储与部署边界

本版为单台持续运行的 Node 服务，使用本地持久文件。data 目录含每日 JSON、编辑候选审计及任务锁，不提交到仓库。
后台使用 Next.js after，关闭网页不影响仍在运行的服务任务；服务进程关闭会中断任务。任务所有者进程失效时允许恢复，生成次数每天最多三次。重试不覆盖已完成的有效早报。

无服务器部署需要替换持久存储和后台任务执行模块，不能依赖临时磁盘或短请求时限。上线前还需确定个人访问控制、会话额度和 HTTPS 域名。本版没有发布公网地址。

## 编辑质量边界

研究阶段让模型搜索并核对原始材料，随后独立整理候选、按相关性和实用性评分、去重、选至多7条，再生成结构化早报。
代码检查来源 URL 来自实际检索返回的引用/来源列表，检查 JSON、唯一 ID、设计和工具分析字段。它不能证明每句事实都正确；重要内容仍应点击来源阅读。证据不足时提示模型放弃入选，分析必须与事实区分。
近期14期的标题与URL传回编辑阶段供跨日去重；同一事件跨日语义去重目前依赖模型判断。未来可增加稳定事件索引和独立事实核验评估。

## 播报行为

输入框左侧“中 / EN”切换播报与问答语言，页面新闻原文保留中文。语言偏好保存在浏览器；播报中切换会重播当前未完成段落，不推进进度。正在录音或回答时语言按钮暂不可用。

右上角日期支持点击选择已保存早报，也支持按住上下滑动（向下较早、向上较新）和键盘上下键。历史记录从 DATA_DIR 的每日文件读取，不重复生成；切换日期停止旧会话，并加载该期内容与独立播放进度。目前为本机持久保存，尚未云端备份。

以短段落为进度单位，须同时收到生成完成和音频缓冲播放结束信号后推进。打断、暂停或停止会使旧播放事件失效。回答后暂停，明确说或输入“继续”才恢复。
允许重说被打断的段落，不保证逐字接续。网络和音频设备缓冲可能影响尾部时序，真实设备验收不能由单元测试代替。
会话内/刷新后的进度保存在当前浏览器 sessionStorage，绑定早报版本。停止不清除进度；点击目录可显式回到故事开头。语音转写用于识别继续/暂停等命令，模型听取用户音频进行回答。

## 验证

npm run typecheck
npm run lint
npm test
npm run build

可选的只读账户检查：node --env-file=.env.local --import tsx scripts/check-api.ts 。仅报告认证与模型可用性，不打印密钥。

真实语音验收：
1. 等待当天早报准备好，点击开始，授予麦克风权限，确认至少三段能听到声音。
2. 在段落开始、中间、末尾分别点击麦克风：播报暂停，录音开始；再次点击结束并发送，答案应围绕当前故事。未点击时，环境声音不得打断播报。
3. 回答后等待，确认没有自动续播；说“继续”，确认恢复未完成段落。
4. 连续两次继续、回答中暂停、停止后重新开始、断网重试。
5. 拒绝麦克风应出现可恢复错误；在实际手机浏览器检查布局和音频权限。

## 依赖理由

Next.js/React：同一项目承载页面和服务端；OpenAI 官方 SDK：类型化 API 和结构化输出；Zod：服务端和测试共用数据校验；tsx：运行 TypeScript 测试；ESLint/TypeScript：静态检查。未引入数据库框架或 Agent 编排系统。
